# Compact scalar token proof and bridge

The active codec adopts layout A. The retained proof also checks the inactive, incompatible layout B; B is not a runtime mode. Layout A uses scalar −1 through −5 for undefined, NaN, positive infinity, negative infinity and negative zero; references use −(id+6). Layout B uses the exact half-integers −0.5, −1.5, −2.5, −3.5 and −4.5 in the same order; references retain −(id+1). Negative finite data remains `[-7,value]`, bigint remains `[-6,decimal]`, and nonnegative finite data and literal strings remain unchanged. Old singleton special arrays are rejected. There is no version field or legacy auto-detection.

`Compact.lean` retains the previous Scalar value and exact numerator/positive-denominator representation, but supplies separate encoders and decoders for both layouts. It proves value round trips, injectivity, disjoint reference/special regions, bounds rejection, singleton rejection, exact arithmetic indices, and the native node-table range below the IEEE754 exact-integer bound. An explicit JSON-tree embedding and inverse prove token-shape round trips and injectivity; this catches scalar-versus-array collisions rather than assuming constructors correspond to distinct JSON.

For layout B the canonical special numbers are negative odd integers over denominator two. The existing Number structure does not quotient arbitrary rational representations: classification of raw 15/10 versus 3/2 therefore requires normalization. The actual structural oracle reduces JSON decimal numbers with `mkRat` before passing them to `Compact.decode`. It emits half markers exactly as a decimal JsonNumber with one fractional digit. All generated graph documents are native JSON.stringify output. Additional scalar lexical cases are parsed with native JSON.parse before transmission to Lean, ensuring decimal rounding is established by the actual runtime first. Raw signed-zero and nonfinite scalar inputs are explicitly tested as runtime rejections outside this finite Number model; they are not silently normalized into ordinary zero or null.

The shared oracle executes the actual compact decode and special encode definitions, then the existing ordered graph/shape decoder and encoder. Its 99 graph corpus covers special values, negative data, aliases, cycles, records and sparse arrays; malformed documents and 35 scalar lexical/type cases compare model acceptance and results with the typed parser. View buffer tokens must use the selected reference offset; URL parameter ownership indices remain raw nonnegative metadata. Native slot/ownership tests are separate from this structural bridge.

JSON parsing/stringification, native IEEE754 classification, allocation identity, getters/iterators and built-in internal slots remain correspondence obligations. The proof does not mechanize a JavaScript engine or claim decoder language equality for arbitrary noncanonical numeric lexemes. Native document numeric canonicalization is part of the executable bridge boundary, not an unstated rational-model restriction. Source observation ordering is unchanged by token representation; transport arrays deliberately change with the adopted compact wire. No performance conclusion follows from these proofs.
