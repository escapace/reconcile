# Serialization fidelity audit

The portable serialization target needs an explicit boundary. Reconcile's in-process contract includes function reference identity, symbol identity and arbitrary existing prototype identity. A standalone text decoder cannot recover those identities without an external registry. Calling a portable serializer a round trip of everything reconcile supports would therefore overpromise.

This audit read the upstream AGENTS.md before implementation files. It made no production changes and ran no tests or benchmarks. Evidence is source inspection and existing tests, not new execution. Local checkout: `973c73fe870ad8b9a791652ba2eee0bbe4b080d1`; inspected upstream: `fd7523fc1a9a1c63333b4d260669331e53e929f5`. Paths below are relative to `/workspace/reconcile-upstream` unless explicitly marked local.

## What is actually preserved

| Surface | Evidence and implication for serialization |
| --- | --- |
| Primitive values | `src/object-property.ts:6` excludes functions from objects; `src/publication/capture.ts:41` stores all nonobjects unchanged. This includes undefined, bigint, symbols, functions, NaN, infinities and negative zero. JSON's ordinary atom vocabulary is insufficient. A portable subset can encode undefined/bigint/special numbers, but function identity and local symbol identity require exclusion or an external reference registry. |
| All graph identities | `src/publication/capture.ts:38` memoizes by the visible source object, before children at line 49. `src/snapshot.ts:79` installs the target in the seen map. | Getters and property descriptors | Object capture reads each named property with Reflect.get, invoking getters. The local implementation in `src/snapshot.ts:39` has the same principal snapshot surface: primitive/function pass-through, WeakMap identity memo, indexed array capture, full buffer copy, view buffer edges, timestamp dates, map keys/values, own names and symbols with retained prototype, and set members. Its recognition uses es-toolkit predicates (`src/object-kind.ts:1`), whereas upstream uses native predicates/instanceof in the type modules. Cross-realm behavior should not be assumed identical. Upstream also replaces local patch/createPatch with produce at the public entry point. Research should name which revision defines the target.

## Recommended portable contract for the experiment

Preserve graph isomorphism and values for ordinary/null-prototype objects, arrays with holes, Map, Set, Date including invalid dates, native ArrayBuffer, native DataView, and an explicit allowlist of installed native typed-array constructors. Include undefined, bigint, NaN, infinities and negative zero as atoms. Preserve full buffer bytes, views' constructor/offset/length and all object identity equivalence classes, including separate equal rich objects. Preserve object string key ordering, including own nonenumerable values if matching snapshot semantics is the chosen target.

Reject unsupported functions, local symbols/symbol keys, arbitrary prototypes/classes, unsupported branded built-ins and unregistered view constructors rather than silently dropping or degrading them. Global/well-known symbols could be an optional later contract; they do not solve local symbol identity. A serialized symbol table can preserve equality relationships *within* a reconstructed graph but cannot make the new local symbol equal to the original symbol, as snapshot does.

Decide explicitly whether to evaluate getters once in snapshot's observation order or reject accessors. If evaluating, do not prewalk and then call JSON.stringify on the original objects: that reads getters again and invokes toJSON, which snapshot does not do. Capture data once into a transport representation. Proxies can be observationally indistinguishable from ordinary objects; an implementation cannot reliably promise to detect/reject every proxy. It can promise an observation policy and ordinary decoded objects.

Special-object expandos are outside snapshot fidelity, but silently accepting and losing them may surprise serialization callers. Either reject them in a strict portable mode or document snapshot-compatible omission. The same decision applies to custom array properties. Descriptor preservation should be a separate opt-in contract, if needed, instead of being inferred from “round trip.”

## Required correctness distinctions

- `{}` versus `{x:undefined}`; holes versus own undefined versus null; empty arrays versus trailing holes.
- NaN, both infinities, negative zero in ordinary slots; invalid Date; bigint with magnitude beyond Number precision.
- One shared node versus two equal distinct nodes, including Date, Map, Set, ArrayBuffer and views.
- Object self cycle, mutual cycle, Map-as-key-of-itself, Map values referencing outer nodes, Set self membership, mixed object/collection cycles.
- Map/Set iteration order and aliases crossing collection keys, values, members and ordinary fields.
- Buffer present explicitly and reachable only through views; two views sharing a buffer but remaining distinct; repeated same view; nonzero offsets, zero-length views at the buffer end, differing element widths, bigint typed arrays, DataView, bytes outside visible ranges.
- Null-prototype objects; integer-like keys with normal JavaScript enumeration order; empty/Unicode/path-looking property names; own `__proto__`, `constructor`, `prototype`, and all metadata-looking literals.
- Own nonenumerable values and accessors under the chosen policy. Explicit rejection outcomes for unsupported values; no success metric that counts silent loss as a pass.

## Limits implied by the contract

JSON.parse alone can only return JSON atoms/arrays/ordinary objects with transport metadata/placeholders. It cannot make cycles, Map/Set, Date, typed arrays, bigint or undefined. A JSON-compatible wire format satisfies syntax interoperability, not semantic interchangeability with arbitrary JSON consumers.

Restoring arbitrary executable prototypes or function behavior from text would require code evaluation or an application registry; neither is justified for this experiment. Native constructor names require an allowlist, not lookup through globalThis or constructor paths. Every object property write on decode should define own data properties, and every reference traversal should use own-property checks, so metadata cannot address inherited `__proto__`/constructor/prototype paths. Unknown tags, duplicate/conflicting metadata, nonexistent/invalid reference targets, excessive counts/depth/bytes, invalid view lengths/alignment and malformed bigints need explicit failure.

The existing snapshot recursion has no resource budget (`src/publication/capture.ts:40` recursively visits via `:59`). A new text decoder processes potentially hostile strings and needs documented input-byte/node/edge/depth/binary allocation limits; it should not inherit the absence of limits merely for fidelity. These can be simple options and validation checks, not a general framework.
